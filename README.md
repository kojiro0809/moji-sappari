# ﾓｼﾞｻｯﾊﾟﾘ Pro (Moji-Sappari Pro)

コピーしたテキストの余計な改行や空白を自動整形し、クリップボードに再格納するデスクトップツールです。大学のレポート作成や、PDFからの引用時に発生する「書式崩れ」のストレスを解消するために開発しました。

##  開発の背景とアプローチ
私は現在、AIを「単なるコード生成機」ではなく「ペアプログラミングのパートナー」として活用し、課題解決に向けたプロダクトを最速で形にする手法を模索しています。

本ツールもプロトタイプはAIと共に数時間で構築しましたが、その後、「エンジニアとして自分が書いたコードの品質に責任を持つ」という観点から、AIが生成したコードの弱点を自己レビューし、以下のリファクタリングを自らの手で実施しました。

## 技術的な課題への取り組み（AIコードからの改善点）

まだ学生であり発展途上の身ですが、プロの現場を意識して以下の3点にこだわって改修しました。

### 1. スレッドセーフなデータ管理（競合の防止）
課題: 当初はUIスレッドと監視スレッドの両方から、蓄積テキスト(`accumulated_text`)に直接アクセスしており、データ破損（レースコンディション）のリスクがありました。
解決策: `threading.Lock()` を導入。変数の読み書き時に明示的に排他制御（ロック）を行うことで、スレッドセーフを担保しました。

### 2. 例外処理の具体化（バグの可視化）
課題: AIが出力した初期コードは `except: pass` となっており、クリップボードの占有エラー等をすべて握りつぶす「危険な設計」でした。
解決策: `PyperclipException` や汎用 `Exception` を個別にキャッチし、エラー内容をUI上に表示して処理を安全に継続する設計に変更しました。

### 3. アーキテクチャの選定理由（ポーリング方式の採用）
設計意図: クリップボードの監視において、OSのイベント駆動（Hook）ではなく `time.sleep(0.5)` によるポーリング方式を採用しています。
理由: CPUリソースを微小に消費するトレードオフはありますが、Windows/Mac等のマルチプラットフォーム環境での動作安定性と、外部ライブラリ依存によるセキュリティリスク低減を優先したためです。

## 実行環境と技術スタック
- 言語: Python 3.x
- GUIフレームワーク: Flet (Flutterベース)
- 主要ライブラリ: pyperclip (クリップボード操作), jaconv (全角半角変換)
